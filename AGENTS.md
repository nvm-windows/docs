# Translation guide for agents

This document describes how the **Russian (`ru`)** locale was added to the NVM for Windows Docusaurus site. Follow it when translating additional locales or updating existing translations.

## Project layout

| Path | Purpose |
|------|---------|
| `docs/` | English source docs (default locale) |
| `i18n/ru/docusaurus-plugin-content-docs/current/` | Russian doc mirror — **translate here** |
| `i18n/ru/code.json` | Theme/UI strings (`Translate` IDs, navbar, certified banner) |
| `i18n/ru/docusaurus-theme-classic/` | Navbar/footer label overrides |
| `static/img/` | Shared images (not duplicated per locale) |
| `src/theme/` | Swizzled theme (certified banner, MDX image helper) |
| `docs/_components/` | Shared MDX/JSX used by English pages |

Docusaurus config: `docusaurus.config.js` — locales `en` + `ru`, `onBrokenLinks: 'throw'`, docs at site root (`routeBasePath: '/'`).

## Sidebar (volunteer-friendly)

Sidebar is **autogenerated** from the docs tree:

```js
// sidebars.js
tutorialSidebar: [{ type: 'autogenerated', dirName: '.' }]
```

Section titles come from **hub pages**, not hardcoded sidebar labels:

- Each folder has `_category_.json` with `"link": { "type": "doc", "id": "…/index" }` and **no** `label`.
- Hub pages (`install/index.md`, `features/index.md`, etc.) set `sidebar_label` / `title` in frontmatter.
- Leaf pages set their own `sidebar_label`.

**For translators:** edit `sidebar_label` / `title` in the **RU mirror** only. Do not duplicate sidebar structure in `sidebars.js`.

Rollback sidebars if needed: `sidebars.js.backup`, `sidebars.js.manual.backup`.

## Dev vs production locales

| Command | URL | Notes |
|---------|-----|-------|
| `npm start` / `npm run start:en` | `http://localhost:3000/` | English only; `/ru/*` 404s |
| `npm run start:ru` | `http://localhost:3000/ru/` | Russian only |
| `npm run build` | `build/` + `build/ru/` | Both locales; **always run before finishing** |
| `npm run preview` | Built site | Test locale switching like production |

The language dropdown does **not** switch locales in single-locale dev — restart with the other script.

## Translation workflow (fast path)

### 1. Find work

```bash
# Stubs left to translate
rg "Перевод готовится" i18n/ru/docusaurus-plugin-content-docs/current/

# Compare file counts (should match docs/ minus drafts)
```

Translate **section by section** (install → features → cfg → guide → command → root pages). Parallel agents work well with one section each.

### 2. For each English page

1. Open `docs/<path>.md` (or `.mdx`).
2. Edit `i18n/ru/docusaurus-plugin-content-docs/current/<path>.md`.
3. **Copy frontmatter structure**; translate `title`, `sidebar_label`, `description` where present.
4. **Keep unchanged:** `slug`, `sidebar_position`, `certified`, `certified_comment`, `draft`, tags, edition names (`Governance`, `Audit`), CLI commands, env vars, registry keys, file paths, URLs.
5. Translate body prose, table **headers/descriptions**, admonition titles, diagram labels.
6. **Do not translate:** code blocks that are literal CLI output, copy-paste commands, JSON/registry examples (unless comments inside).

### 3. Reusable components

| Type | Pattern |
|------|---------|
| **Prose MDX** (e.g. `SymlinkPermissionExplainer.mdx`) | Mirror under `i18n/ru/.../current/_components/`. Page imports with **relative** path (`../../_components/Foo.mdx`) — RU pages resolve the RU copy automatically. |
| **No-text JSX** (e.g. `DocImage.jsx`) | Single file at `docs/_components/DocImage.jsx`. Import from RU pages: `import DocImage from '@site/docs/_components/DocImage';` |
| **Tables in MDX** (version resolution) | Mirror + translate under `i18n/ru/.../current/_components/`. |

MDX v3 **does not** auto-register custom components from theme. Any `<DocImage>` / custom JSX needs an explicit `import`.

### 4. Images

- Markdown: `![alt](/img/...)` — handled by `src/theme/MDXComponents.js` (`useBaseUrl` for `/img/` paths).
- JSX with styles: use `<DocImage src="/img/..." alt="..." style={{...}} />` + import (see above).
- Static files live in `static/img/` once; RU locale serves them at `/ru/img/...` in dev.

Translate `alt` text in RU pages; image files stay shared.

### 5. Certified build banner (theme UI)

Hardcoded UI is **not** in markdown. Banner logic: `src/theme/DocItem/Layout/index.js`.

Strings use `@docusaurus/Translate` with IDs in `i18n/ru/code.json`:

- `certifiedBanner.badge`
- `certifiedBanner.releaseDate`
- `certifiedBanner.availability`
- `certifiedBanner.requiresEdition`

Per-page custom banner text: translate in frontmatter:

```yaml
certified_comment: "…"
# or
certified:
  edition: governance
  comment: "…"
```

`certified: true` and edition names stay as in English source.

### 6. Diagrams

Translate diagram **labels**, not structure:

| Kind | Example file | Action |
|------|--------------|--------|
| Mermaid | `features/modes.md` | Translate node text; keep `flowchart LR` syntax |
| ` ```text ` trees | `local-installations.md`, `air-gapped-installations.md` | Translate comments; keep paths/filenames |
| GPO policy tree | `cfg/enterprise/ad.md` | Translate policy names + Windows path labels; note ADML may show English in editor until localized ADML is installed |
| Repo tree | `install/source.md` | Translate `#` comments on each line |
| CLI sample output | `command/env.md` | **Keep English** — matches real tool output |

### 7. Heading anchors (critical for MDX)

English headings auto-generate slugs like `#mode-and-install-location`. Russian headings generate **Cyrillic** slugs, which breaks cross-links from other RU pages.

**Fix:** append explicit IDs with a **backslash escape** (MDX v3 treats `{#id}` as JS otherwise):

```markdown
## Режим и каталог установки \{#mode-and-install-location}
```

Add `\{#…}` on any heading targeted by links elsewhere. Common IDs:

- `cfg/core.md`: `mode-and-install-location`, `downloads-and-mirrors`, `proxy`, `logging-and-announcements`, …
- `features/modes.md`: `link-mode`, `shim-mode-default`
- `cfg/registry.md`: `available-registry-keys`, `governance-keys`
- `install/enterprise/requirements.md`: `proxy-exceptions`
- `permissions.md`: `community-installer-registered-event-source`
- `command/config/reset.md`: `reset-all`
- `install/uninstall.md`: `community-builds`

After adding anchors, run `npm run build` and fix any broken-anchor warnings.

### 8. Internal links and slugs

Most links: keep the **same relative paths** as English (`../features/modes`, `./installers#community-build`).

**Exception:** pages with custom `slug` in frontmatter sit shallower in the URL tree than their folder path. Use one fewer `../` when linking **out** from these pages:

| File path | `slug` | Link to `install/enterprise/intune` |
|-----------|--------|-------------------------------------|
| `cfg/enterprise/ad.md` | `/cfg/ad` | `../install/enterprise/intune` (not `../../…`) |
| `cfg/enterprise/registry.md` | `/cfg/registry` | `../features/mirrors` (not `../../…`) |

`onBrokenLinks: 'throw'` catches wrong depth in RU builds.

### 9. Redirect

Both locales need locale-aware home redirect:

```jsx
// docs/index.mdx and i18n/ru/.../index.mdx
import useBaseUrl from '@docusaurus/useBaseUrl';
import {Redirect} from '@docusaurus/router';
return <Redirect to={useBaseUrl('/install/installers')} />;
```

## Verification checklist

```bash
cd docs_guide/docs

# No stubs
rg "Перевод готовится" i18n/ru/

# Full build (required)
npm run build

# Optional: spot-check RU
npm run start:ru
# → http://localhost:3000/ru/install/installers
```

Build must pass **both** `en` and `ru` with zero link errors. Anchor warnings should be cleared before merge.

## Parallel agent split (recommended)

When adding a new locale or large update, assign one agent per section with this prompt skeleton:

```
Translate i18n/<locale>/docusaurus-plugin-content-docs/current/<section>/
from docs/<section>/.
Rules: [paste "Translation workflow" + "Heading anchors" + "Internal links" from this file]
Return: files translated, anchor IDs added, build errors fixed.
```

Merge, then one agent runs `npm run build` and fixes cross-section link/anchor issues.

## Adding a new locale (outline)

1. `docusaurus.config.js` — add locale to `i18n.locales` and `localeConfigs`.
2. `npm run write-translations` — seed `i18n/<locale>/code.json`.
3. Copy `docs/**` tree to `i18n/<locale>/docusaurus-plugin-content-docs/current/` (or write-translations for docs plugin if configured).
4. Add `i18n/<locale>/docusaurus-plugin-content-docs/current/index.mdx` redirect with `useBaseUrl`.
5. Mirror `_components/` as translations are done.
6. Add `start:<locale>` script in `package.json`.
7. Translate hub `sidebar_label` values and `i18n/<locale>/docusaurus-theme-classic/*.json` if needed.

## Common failures and fixes

| Symptom | Cause | Fix |
|---------|-------|-----|
| `/ru/*` 404 in dev | Running `npm start` (en only) | `npm run start:ru` |
| Images 404 on RU pages | Bare `/img/...` without `useBaseUrl` | Use `DocImage` or markdown `![]()` (MDXComponents) |
| `DocImage is not defined` | MDX v3 needs import | `import DocImage from '@site/docs/_components/DocImage';` |
| MDX `Could not parse expression with acorn` | `{#anchor}` in heading | Use `\{#anchor}` |
| RU build broken links to `/install/...` (no `/ru`) | Too many `../` from sluggified page | Reduce path depth (see slugs table) |
| Broken anchor warnings | Cyrillic auto-slugs | Add `\{#english-anchor-id}` to RU heading |
| RU requirements imports missing component | Relative import to `_components` | Ensure `i18n/ru/.../current/_components/` exists |

## Do not translate blindly

- Product/edition names: `Governance`, `Audit`, `Trust`, `Certified Build` badge edition token in frontmatter
- GPO/Intune UI strings that must match English ADML until localized packs exist (document this in prose; diagram can be translated for readability)
- `nvm …` commands, PowerShell literals, registry key names (`MirrorNode`, `ProxyAuthType`)
- GitHub paths, version numbers, `%ProgramFiles%` paths

## Files agents should read first

1. This file (`AGENTS.md`)
2. English source page being translated
3. Existing RU page (if partial) in `i18n/ru/.../current/`
4. `docusaurus.config.js` (locales, broken link policy)
5. `src/theme/DocItem/Layout/index.js` (certified banner behavior)

## Commit guidance

Translation-only changes are safe to batch by section. Always include `npm run build` success in PR test plan. Do not commit unless the user asks.
