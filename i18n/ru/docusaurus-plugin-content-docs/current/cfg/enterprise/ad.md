# Административные шаблоны (Intune и GPO)

Certified governance-сборки NVM for Windows поставляются с шаблонами ADMX/ADML. Используйте их в **локальной групповой политике** или **профилях конфигурации Microsoft Intune**.

|Ресурс|Руководство|
|:-|:-|
|Файл ADMX| Управляет техническими параметрами реестра. Доступен на [portal.author.io](https://portal.author.io).|
|Файл ADML| Текст интерфейса для параметров. Доступен на [portal.author.io](https://portal.author.io).|
|Целевой путь| `HKLM\Software\Policies\Author Software\nvm`|

Скачайте ADMX/ADML с [клиентского портала](https://portal.author.io). Для установки Win32-приложения через Intune см. [Установка → Intune](../install/enterprise/intune).

## Настройка политики Intune

После [установки](../install/enterprise/intune) NVM for Windows применяйте параметры через импортированный административный шаблон.

### 1. Импорт ADMX и ADML

1. В [центре администрирования Intune](https://go.microsoft.com/fwlink/?linkid=2109431) перейдите в **Devices** > **Windows** > **Configuration**.
1. Откройте вкладку **Import ADMX** и выберите **Import**.
1. Загрузите `NVMWindows.admx` и `en-US\NVMWindows.adml` из пакета развёртывания. Предварительный `Windows.admx` не требуется.

:::warning[ошибка **131329** (0x20101)]
1. На устройстве запустите `certified\enhanced\policy\Get-NvmAdmxIngestDiagnostics.ps1` и запишите **HRESULT** в событиях `ADMX Ingestion` (например, `0x8007000D` — недопустимые данные ADMX, `0x80070005` — заблокированный путь реестра).
1. Удалите предыдущий импорт NVM ADMX в Intune, затем повторно импортируйте обновлённый шаблон.
1. Очистите устаревшее состояние ingest на устройстве, затем снова выполните синхронизацию:

```powershell
Remove-Item -Recurse -Force "$env:ProgramData\Microsoft\PolicyManager\ADMXIngestion\*nvm*" -ErrorAction SilentlyContinue
Get-ChildItem 'HKLM:\SOFTWARE\Microsoft\PolicyManager\AdmxInstalled' -Recurse |
  Where-Object { $_.Name -match 'nvm' } |
  Remove-Item -Recurse -Force
```

Пока ingest ADMX не завершится успешно, развёртывайте значения через профиль конфигурации **Custom** (Registry CSP OMA-URI). Имена и типы значений — в [центральном справочнике реестра](registry).
:::

![alt text](/img/guide/deploy/policy/image-1.png)

### 2. Создание профиля конфигурации

1. Перейдите в **Devices** > **Configuration** > **Create** > **New policy**.
1. Платформа: **Windows 10 and later** (включает Windows 11 и Windows Server 2019 и новее).
1. Тип профиля: **Templates** → **Imported Administrative templates**.
1. Перейдите в **Author Software** > **NVM for Windows** и настройте политики.

![alt text](/img/guide/deploy/policy/image-2.png)

Имена политик совпадают с деревом GPO ниже. Имена значений реестра — в [центральном справочнике реестра](registry).

:::tip[Альтернатива Registry CSP]
Отдельные значения реестра можно развёртывать через профиль **Settings catalog** или **Custom** с Registry CSP OMA-URI. Предпочитайте импорт ADMX, когда он доступен; Registry CSP — запасной вариант или для отдельных ключей. См. [центральный справочник реестра](registry).
:::

## Развёртывание групповой политики (GPO)

:::info[Доступ к контроллеру домена]
Для задач в этом разделе нужен доступ к контроллеру домена.
:::

_На контроллере домена:_

1. Скопируйте `NVMWindows.admx` в `\\domain\sysvol\domain\Policies\PolicyDefinitions`.
1. Скопируйте `en-US\NVMWindows.adml` в `\\domain\sysvol\domain\Policies\PolicyDefinitions\en-US`.
1. Откройте редактор управления групповой политикой (`Win + R`, введите `gpedit.msc` и нажмите **Enter**.)
1. Найдите объект групповой политики (или создайте новый) для управления политиками Node.js. ПКМ → **Edit**.
1. Перейдите в **Computer Configuration** > **Policies** > **Administrative Templates** > **Author Software** > *NVM for Windows*.

![GPO](/img/guide_gpo.png)
